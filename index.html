Production 30 repos · advisory

AI-Assisted DevOps Automation

As the team adopted Claude Code, AI-generated code volume went up and human PR review became the bottleneck. I customized Anthropic's official Claude Code GitHub Action into a review agent running across 30 repositories and two product teams plus the platform team: triggered when a PR opens, it pulls the linked Jira ticket, compares what was asked against what was delivered, and flags exposed secrets — with per-repo tuned prompts for infrastructure versus application code. It's advisory, not a blocking check, on purpose: a non-deterministic reviewer as a required gate stops people on false positives until someone switches it off. Advisory means it has to earn its place — and it's caught real requirement gaps and exposed secrets before merge.

Production 10% traffic · 15-min window

Canary Releases for ML Predictions

A Lambda function serving predictions from a SageMaker model — built with a data science team, reading and writing through Redshift on both ends — was shipping single-cutover: a new version took 100% of production traffic immediately, and a bad model meant someone manually redeploying the previous one to recover. My piece of that pipeline was the release path. AWS CodeDeploy now routes 10% of traffic to a new version for a 15-minute canary window while CloudWatch Alarms watch error rate and p95 latency; a 0.5% error-rate breach during that window auto-aborts the deployment and rolls back to the previous version, no manual intervention required. It's the same canary standard the platform team already ran elsewhere, applied here. The team ships prediction-service updates during regular business hours now, instead of avoiding risky release windows.
