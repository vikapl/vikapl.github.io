Hyatt Hotels Corporation · Production 10% traffic · 15-min window

A canary release that catches its own mistakes

Hyatt's Lambda-based prediction service — a SageMaker model reading and writing through Redshift — shipped all at once: a new version took 100% of production traffic immediately, so a bad release became a full incident before anyone noticed. I configured AWS CodeDeploy to hold new versions to 10% of traffic for a 15-minute canary window, with CloudWatch alarms watching error rate and p95 latency; a 0.5% error-rate breach aborts the deployment automatically and shifts traffic back to the previous version — no one has to be watching a dashboard and deciding by hand. It was the platform team's established standard across their services, which I applied here.

Hyatt Hotels Corporation · Production 30 repos · advisory

A reviewer that reads the ticket, not just the diff

As the team adopted Claude Code, AI-generated code volume went up and human PR review became the bottleneck. I customized Anthropic's official Claude Code GitHub Action into a review agent running across 30 repositories and two product teams plus the platform team: triggered when a PR opens, it pulls the linked Jira ticket, compares what was asked against what was delivered, and flags exposed secrets — with per-repo tuned prompts for infrastructure versus application code. It's advisory, not a blocking check, on purpose: a non-deterministic reviewer as a required gate stops people on false positives until someone switches it off. Advisory means it has to earn its place — and it's caught real requirement gaps and exposed secrets before merge.

Personal project · built & tested, not deployed

Teaching an incident responder where to stop

Watching alerts fire is one problem. Deciding what's safe to fix without asking first is a different, harder one. I built an EventBridge + Lambda pipeline that diagnoses a CloudWatch/EKS incident and checks it against two independent gates — an account-wide switch that's off by default, and a per-incident-type allow-list that deliberately never includes anything ambiguous. Only two actions are ever automatable: a rollout restart, or a one-node nodegroup bump capped at its own maximum size. Everything else — and every decision either way — gets posted to Slack. I've validated it end-to-end against three real CloudWatch alarm fixtures; the Terraform is written but not applied, and it hasn't touched a live cluster yet, which I'd rather say plainly than let the writeup imply otherwise.
